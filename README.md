# Где теряются покупки в интернет-магазине

Пет-проект по продуктовой аналитике интернет-магазина. На событиях из Kaggle можно измерить переходы от просмотра товара до покупки. Отдельная симуляция показывает, как разобрать причины отказов при оформлении и спроектировать A/B-тест для одного из сценариев.

| Часть | Данные | Что можно узнать |
| --- | --- | --- |
| Воронка магазина косметики | [REES46](https://rees46.com/en/datasets) · [Kaggle](https://www.kaggle.com/datasets/mkechinov/ecommerce-events-history-in-cosmetics-shop) | Какая доля сессий доходит от просмотра до корзины и от корзины до покупки |
| Отказы после отправки заказа | Синтетические события, генерируемые скриптом | Как считать повторные попытки, восстановление после ошибки и вклад разных причин отказа |
| Подсказка при изменении стоимости доставки | Описание интерфейса и протокол A/B-теста | Как проверить изменение перед внедрением |

## 1. Воронка на данных Kaggle

Единица анализа — сессия, определяемая парой `user_id` и `user_session`. Первое добавление в корзину после просмотра открывает следующий шаг. Покупку учитываем после этого добавления в пределах той же сессии. Несколько покупок в одной сессии дают один переход. При совпадении временных меток события считаются одновременными и могут образовать переход. Воронка описывает действия на уровне сессии: просмотр, добавление и покупка могут относиться к разным товарам.

В источнике `price` — цена товара. Для оценки сценария с доставкой понадобились бы обе версии стоимости доставки, события отправки заказа и коды серверных отказов. В датасете REES46 эти поля отсутствуют. Отдельные месячные выгрузки могут обрезать сессии на границах периода.

### Запуск

Нужен Python 3.9 или новее. Используется стандартная библиотека.

1. Скачайте `2019-Oct.csv` (около 483 МБ без сжатия) из [датасета Kaggle](https://www.kaggle.com/datasets/mkechinov/ecommerce-events-history-in-cosmetics-shop) и распакуйте в папку `data`.
2. Выполните команду.

```bash
python analyze_kaggle.py data/2019-Oct.csv
```

Скрипт загружает CSV в SQLite, рассчитывает метрики через [SQL-запрос](sql/kaggle_funnel.sql) и сохраняет `reports/kaggle_funnel.csv`. В консоли выводятся число загруженных событий и число пропусков из-за неполных идентификаторов сессии. CSV можно открыть в Excel.

## 2. Сценарий с изменением стоимости доставки

Покупатель увидел доставку за 199 ₽. К моменту отправки заказа цена стала 249 ₽, а интерфейс вернул общее сообщение об ошибке. По данным об ответах сервера можно выделить эту причину и посмотреть, сколько людей возвращаются к оформлению.

```bash
python simulate_checkout.py
```

| Шаг в синтетической воронке | Пользователи |
| --- | ---: |
| Открыли корзину | 1 000 |
| Перешли к оформлению | 800 |
| Отправили заказ | 600 |
| Получили подтверждение в течение 10 минут после первой попытки | 505 |

Из 90 пользователей, получивших отказ из-за смены стоимости доставки, 42 повторили попытку, а 30 оформили заказ в пределах окна. Доля восстановления — **33,3%**. Эти значения заданы симуляцией и служат для проверки расчётов.

Выгрузки: [воронка](reports/synthetic_funnel.csv) и [разбивка ошибок](reports/synthetic_failure_breakdown.csv).

## 3. Гипотеза и A/B-тест

Если показать новую стоимость и итог заказа прямо на экране оформления, больше людей смогут завершить заказ. Экран сохраняет корзину и предлагает подтвердить новую цену или выбрать другой способ доставки.

Контроль видит обычное сообщение об ошибке, тест — новую подсказку. Случайное назначение идёт по пользователю при первом подходящем серверном отказе. Основная метрика — доля назначенных пользователей, которые получили подтверждение по той же корзине в течение 10 минут. Дополнительно отслеживаются заказы за 24 часа и отмены.
